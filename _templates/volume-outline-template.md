## AI 交互流程

卷纲的交互是**草案→审核→修改→拍板**的循环。和大纲不同——大纲是逐段由你填，卷纲是 AI 先生成整份草案，你再逐块审。

### 第一轮：AI 生成草案

```
AI 自动读取：
  □ _outline/{book}/outline/book.md（大纲——分卷规划 + 主角弧光 + 核心设定）
  □ _outline/{book}/novel_state.yaml（小说当前状态——角色在哪、伏笔进度、时间线）
  □ 上一卷的卷纲（如果不是第一卷——前卷的落点是什么、有哪些跨卷伏笔）

AI 生成卷纲草案，写入 _outline/{book}/volumes/volXX.md，然后告诉你：
  "卷纲草案已生成。共 N 幕 M 章，核心事件是 XX，卷末落点在 YY。
   建议你先看三个地方——
   ① 幕结构：节奏符不符合你想讲的故事？
   ② 章节分布：有没有太赶或太拖的？
   ③ 爽点节奏：有没有连续同类或分布不均？
   看完告诉我哪里改。"
```

### 第二轮：你逐块审核

```
你审完后告诉 AI：
  - "第二幕太长了，拆成两幕"
  - "第 5 章的打脸爽点和第 3 章重复了"
  - "伏笔 XX 应该在本卷回收，加进第 N 章"

AI 修改 → 重新生成 → 你再审 → 循环到你满意。
```

### 第三轮：AI 做一致性检查

```
你拍板后，AI 自动跑一份检查：
  □ 卷纲的每件事，都在大纲的分卷规划里有依据吗？
  □ 爽点类型没有连续 2 章以上重复？
  □ 每 3 章至少有一个爽点时刻？
  □ 伏笔规划没有"埋了但忘了"的？
  □ 角色出场次数和关键配角表匹配吗？

AI 输出检查结果：
  - 🟢 全部通过 → 卷纲就绪，可以开始写章纲
  - 🟡 有小问题（列出）→ 你决定修还是跳过
  - 🔴 有矛盾（列出）→ 必须修完再开始章纲
```
